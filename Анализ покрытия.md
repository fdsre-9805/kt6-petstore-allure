## Разбор расхождений

- Сервер возвращает 500 при неверном числовом типе ID в JSON для семи операций: создание и изменение питомца, создание заказа, создание пользователя одиночно/списком/массивом и изменение пользователя. Примеры ответа: code 500, message "something bad happened". У операций user с default точный ожидаемый 400 является допущением.
- В четырёх операциях GET/DELETE по ID питомца и заказа вместо документированного 400 получен 404 с java.lang.NumberFormatException. Отдельно POST формы питомца возвращает 404 вместо указанного 405.
- uploadImage с нечисловым petId вернул 404; ожидаемый 400 в этом тесте принят нами: в Swagger у загрузки определён только успешный ответ.
- Поиск с invalid_status и поиск без обязательного tags возвращают 200 и пустой массив вместо отказа.
- Склад возвращает остатки с invalid-key; в Swagger есть security api_key, но конкретные ошибочные коды не описаны. Тест ожидает 401 или 403.
- Вход с неверным паролем возвращает 200 и "logged in user session" вместо документированного 400.
- Получение и удаление отсутствующего пользователя возвращают ожидаемый 404. PATCH /user/logout возвращает ожидаемый 405.

## Соответствие презентации

1. Терминал Ubuntu доступен напрямую; WSL из слайдов 3–4 не нужен на Ubuntu.
2. pytest-cov установлен в локальную .venv, а не системный Python.
3. --cov=api_client задаёт именно исходный код клиента, аналогично --cov=src в примере.
4. --cov-report=term-missing даёт таблицу строк, --cov-report=html:htmlcov — HTML.
5. Разобраны фактические результаты и непокрытые возможности; процент не выдан за доказательство качества.

## Очистка и ограничения общего сервера

Питомцы и пользователи имеют случайные идентификаторы и префикс kt6_.
Заказ создаётся только на найденном свободном ID 1–10; после теста удаляется
только если petId совпадает с нашим. Ни одного skip в данном прогоне нет.
Фикстуры очистки завершились без ошибок. После удаления в части позитивных
тестов дополнительно проверен GET 404; для остальных очистка подтверждена
ответом DELETE, отдельный GET после teardown не выполнялся.
Между проверкой ID заказа и записью возможна гонка на общем сервере.
Массовой очистки чужих записей, повторов до удобного статуса и зависимости
тестов от порядка нет. Подключение к учебному серверу разрешено пользователем.
